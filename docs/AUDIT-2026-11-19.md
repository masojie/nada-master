# Audit teknis NADA Master - 2026-11-19

Target: `masojie/nada-master` @ `15f7d78` (folder `src/` identik dengan `8100aeb`, dicek dengan `git diff`).
Metode: baca seluruh kode, jalankan suite resmi, plus tes tambahan dengan sinyal sintetis, pembanding ffmpeg (ebur128, FLAC), libsndfile, scipy (true peak 16x), dan parser HTML.

## A. Ringkasan

- Inti DSP kuat: meter BS.1770-4/EBU R128 lolos EBU Tech 3341 #1-4 dan 3342 #1-4 di 44.1/48/96/192 kHz (error maks 0,041 LU), koefisien K-weighting identik tabel BS.1770-4, latensi oversampler tepat (47/54/56 sampel), dither benar, FLAC/WAV bit-exact terhadap ffmpeg dan libsndfile, render deterministik bit-identik.
- Masalah terbesar di jalur analisis ke koreksi adaptif (aktif default): boost air +2,5 dB palsu di semua file 44,1 kHz dan notch resonansi palsu di 150-190 Hz.
- Suite resmi (`npm test`, sama dengan CI): 11 file, 568 assertion lulus, 0 gagal, 4 TODO (bug yang sudah dicatat).
- Total 18 temuan: CRITICAL 0, HIGH 1, MEDIUM 8, LOW 9.

## B. Arsitektur

Vanilla JS (ES modules), tanpa dependency. `build.mjs` (bundler buatan sendiri) menghasilkan `dist/index.html` satu file plus `dist/engine-worker.js`; hosting statis Vercel; CI GitHub Actions (Node 22/24). Tanpa backend, database, API eksternal, atau storage.

Alur: UI (`src/ui/app.js`) -> worker (`src/worker.js`): decode -> `analyzeAudio` -> `resolveSettings` -> `planAdaptive` -> `renderMaster` (pre, EQ, DynEQ, comp, multiband, saturasi oversampled, stereo, tone, clipper + limiter true peak + pencarian loudness) -> `runQC` -> `exportAudio` (SRC + safety limiter, dither, encode, decode ulang untuk verifikasi). Player A/B memakai dua AudioBufferSourceNode sinkron.

Kelemahan arsitektur: kode sangat padat, nilai sentinel dB (-200/-600) bercampur dengan nilai asli (akar NM-01/NM-02), seluruh file diproses di memori dengan banyak salinan, state UI berupa satu objek mutable.

## D. Keamanan

Positif: tanpa secret, tanpa network call, tanpa eval, tanpa storage, audio tetap di perangkat, nol dependency, CI `permissions: read`. Temuan: NM-08, NM-04/05 (DoS lewat file rusak). Tambahan LOW: `vercel.json` tanpa security header; action CI di-pin ke tag. Risiko belum terverifikasi: bom dekompresi FLAC (blok CONSTANT).

## E. Performa (Node 24, 1 vCPU, 30 s stereo 44,1 kHz)

Analisis 0,82 s + render 4,39 s (5,8x realtime); export WAV 0,4 s, FLAC24@48k 3,3 s, FLAC16@96k 5,5 s; maxRSS 131 MB.
PERF-1 DynEQ menjalankan dua filter identik. PERF-2 pencarian loudness mengalokasi buffer limiter tiap pass. PERF-3 encoder FLAC lambat (bit writer memakai Math.pow, pencarian partisi berulang). PERF-4 banyak salinan full-length (estimasi 2,9 MB per detik audio di worker).

## F. Audio engine

LUFS/LRA lolos; true peak: lihat NM-03/NM-15; oversampler dan clipper transparan; limiter menahan sample peak tepat di ceiling; dither TPDF RMS 0,500 LSB (teori 0,500), noise shaping -16..-18 dB di bawah 5 kHz dan +17 dB di 15-22 kHz; codec dan export bit-exact; render deterministik. Observasi desain: detector DynEQ bersifat peak sedangkan threshold otomatis dari RMS; detector resonansi juga menandai nada musikal yang bertahan.
